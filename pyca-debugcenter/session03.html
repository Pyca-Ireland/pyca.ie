Streaming — SSE Implementation

The streaming pipeline has three layers and a known proxy problem that was resolved:

Student browser │ ├── fetch("/api/chat", { method: "POST" }) │ ↓ │ Next.js Route Handler (app/api/chat/route.ts) │ — pipes upstream.body directly, no buffering │ — headers: Cache-Control: no-cache, no-transform │ ↓ │ FastAPI StreamingResponse (main.py) │ — media_type: text/event-stream │ — yields JSON lines from stream_chat() generator │ ↓ │ stream_chat() generator (science_v3/agent.py) │ 1. yield {"type": "sources", "data": [...]} │ 2. OpenAI stream=True → yield {"type": "token", "data": "..."} × N │ 3. yield {"type": "done"}

Critical bug resolved: Next.js rewrites in next.config.ts buffer the entire SSE response before forwarding it, causing the response to appear all at once. Fixed by replacing the rewrite with a Route Handler (app/api/chat/route.ts) that pipes upstream.body directly as a Response.

Auto-Sidebar

The sidebar auto-opens whenever the AI response mentions at least one question ID. It stores the cited sources from the most recent response.

// After streaming done event:
const cited = referencedSources(finalContent, pendingSources);
if (cited.length > 0) {
    setSidebarSources(cited);
    setSidebarOpen(true);
}

Question IDs are detected by matching the AI response text against /\b(\d{4}-[A-Z]+-[A-Z]+-Q\d+)\b/g. Only questions the AI actually cited are shown — not all retrieved sources. Width: 480px. Closing the sidebar reveals a "Questions (n)" button in the nav to reopen.

QuestionModal

Triggered by clicking any source card in the sidebar, or by clicking a bold inline question ID in the AI response text. The inline IDs are rendered by preprocessing the AI's markdown before passing to ReactMarkdown:

// [2023-AB-HL-Q5] → [**2023-AB-HL-Q5**](exam://2023-AB-HL-Q5)
function preprocessContent(content: string): string {
    return content.replace(
        /\[(\d{4}-[A-Z]+-[A-Z]+-Q\d+)\]/g,
        (_, rid) => `[**${rid}**](exam://${rid})`
    );
}

// ReactMarkdown custom 'a' component intercepts exam:// hrefs
a({ href, children }) {
    if (href?.startsWith("exam://")) {
        const rid = href.slice(7);
        return ;
    }
}

The modal layout: image panel (left, flex-1) with page navigation for LONG questions; detail panel (right, w-72) with all ExamQuestionObject fields. Fetches /api/question/{exam_rid} lazily on open. Closes on ✕, Escape, or click outside.

Technical Analysis — MVP-Sprint2

RAG Pipeline Architecture

User query (natural language) │ ├── OpenAI text-embedding-3-small │ → 1536-dimensional float vector │ ├── Pinecone cosine similarity search │ → top-5 ExamQuestionObject vectors │ → optional pre-filters: year, level, paper, type (metadata) │ ├── stream_chat() builds context block: │ "[EXAM_RID] YEAR | PAPER | LEVEL | QN | TYPE | Mm\n{ocr_text}" │ Injected only into the LAST user turn of the history │ └── OpenAI gpt-4o-mini (stream=True) System prompt: LCCS assistant rules Messages: [system] + full conversation history with context injected → Streamed token-by-token to browser

Context injection strategy: RAG context is injected only into the last user message, not the system prompt. This keeps the system prompt clean and stable across turns, while the retrieved context stays relevant to each individual query. Previous assistant turns in the history have no injected context — only their plain responses.

Multi-turn history: The frontend sends the full conversation history with every request. The backend uses the last user message as the Pinecone query, ensuring retrieval is always based on the most recent intent, not the entire conversation.

SSE Protocol Design

The SSE stream uses three event types delivered as newline-delimited JSON over text/event-stream:

Event typeTimingPayload
sourcesFirst — before any tokensArray of source dicts from Pinecone results
tokenRepeated — one per OpenAI chunkString fragment of the AI response
doneLast — after all tokensEmpty — signals stream end

Sources are sent first deliberately: the frontend can begin rendering sidebar cards and inline citation links while the text is still streaming in. The done event triggers the source detection pass (regex over the full content) to determine which cited question IDs to show in the sidebar.

System Prompt Design & Safeguards

Seven explicit rules govern the AI's behaviour:

  1. Greetings rule — respond naturally for casual messages; do not mention the database.
  2. Genuine relevance rule — only cite a question by ID if it is genuinely relevant; do not stretch connections.
  3. No-results honesty rule — if asked about a specific topic with no matching questions, say so clearly.
  4. No OCR quoting rule — never reproduce raw OCR text verbatim; paraphrase only.
  5. Card auto-display rule — question card appears automatically on ID citation; do not describe the full question text.
  6. Topic scope rule — LCCS exam content and computer science curriculum only.
  7. No marking scheme speculation — do not guess answers; note marking schemes are coming soon.

Known limitation: Without a score threshold, the Pinecone retrieval always returns 5 results regardless of relevance. The AI may receive weakly relevant context. Rule 2 (genuine relevance) and Rule 3 (no-results honesty) are the primary safeguards against hallucinated connections. A score threshold was prototyped at 0.72 cosine similarity but removed at user request — keeping the AI's judgement as the single filter.

Frontend State Management

All state lives in a single page.tsx client component — no external state library:

StateTypePurpose
messagesMessage[]Full conversation including streaming placeholder
filtersFiltersActive metadata filter values
filtersOpenbooleanFilter bar visibility
streamingbooleanDisables input during active SSE stream
sidebarSourcesSource[]Cards from last response that cited question IDs
sidebarOpenbooleanSidebar visibility; auto-set true when new cards arrive

The streaming assistant message is added to state immediately as an empty placeholder with streaming: true. Token events append to its content field in-place via setMessages(prev => prev.map(...)). The done event sets streaming: false, which removes the blinking cursor and triggers source detection.
